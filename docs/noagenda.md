# NoAgenda (Android): the core step (read only), then editing (step 2 below)

Binding spec: `plans/noagenda-decisions.md` (approved 2026-10-28). Platform plan: `plans/noagenda-android-plan.md`, section 1
("agenda-core"). This page describes what is built in the first step, how it is tested and what the next steps will add. The edit
step (editing, offline queue, conflicts), the Timeline and the phone's own Calendar and Contacts sync come in their own branches.

## What the user gets

- **NoAgenda** as the **first item of the side menu's Apps section**, above the server's Workspace apps. It opens the NoAgenda screen
  for the current account.
- **Day, Week and Month lists** of everything the person is responsible for: NoCalendar events, NoTasks to-dos, NoGantt tasks and
  milestones, NoBoard cards. Each row shows the kind, the title, when, the source in its colour and who does it (an agent's name or
  **Self**).
- The three kinds of work (do it myself, supervise my agent, oversee my team) with the chips **Me / My agents / My team** and the
  **All / Work / Personal** switch.
- **My team**: only the problems in what the person runs (late, due today, blocked, someone overbooked, not assigned to a person, the
  agent and sharing problems of design 4.4), with the switch **Show all team tasks**.
- **Sources** screen with the defaults of design 6.1 (a drop-down for every calendar, project and board), the working hours and the
  agents of the registry. The one-time question **"Which of your calendars are personal?"** comes once, after the first calendar read.
- A saved copy for **offline** use ("showing what was saved at 10:42"), and a **background refresh** about every 15 minutes (WorkManager).
- **Nothing can be changed in this step.** The detail sheet only offers "Open in NoCalendar / NoTasks / NoGantt / NoBoard", which opens
  the page of the account's own server, signed in, inside the app (the same hand-off as the Workspace apps).

## How it reads (design section 5)

Every request goes through the account's own client and its own app password, to the account's own server only.

- **NoGantt** routes are OCS routes: `ocs/v2.php/apps/nc_gantt/api/v1/...`, with `OCS-APIRequest: true` and `format=json` (the design's
  table says `/apps/nc_gantt/api/v1`; that is not the real path). NoGantt shows no version to a normal user, so the **version guard** is the
  contract check in `gantt/GanttContract.kt`: every answer must have the keys and types of 2.4.1. A mismatch shows the NoGantt rows read
  only with "Open in NoGantt".
- **NoBoard** (Deck REST `index.php/apps/deck/api/v1.0`): guard is `capabilities.deck.version`; only 1.19 counts as tested, another
  major or minor is shown read only with "Open in NoBoard". The request carries `OCS-APIRequest: true`.
- **CalDAV**: PROPFIND of the principal and of the calendar home; a calendar is read again only when its sync token (or ctag) changed,
  with one `calendar-query` for the events of the window (expanded by the server) and one for the not completed to-dos (never expanded:
  the server drops every VTODO on expand). A calendar that fails keeps its old records. The window is the previous month to 12 months ahead.
- **Registry**: `GET remote.php/dav/files/<user>/NoAgenda/agent-registry.json` with `If-None-Match`.
- If NoGantt or NoBoard answers 401 or 403 while the account is fine, that source is **refused**: a banner says it and offers
  "Open in NoGantt" / "Open in NoBoard". The status code is logged; no credential ever goes to another host.

## Rules that are tested

Defaults of design 6.1; the event rules (free events do not block time, declined invitations are hidden, tentative ones are soft, a team
calendar shows only what I organise or am invited to, an invitation is always Self, the same invitation in two calendars is one row);
agents in each home (`X-NOURAX-AGENT-ID` and the registry's calendar tag, board labels, NoGantt planning people by registry id or by the
exact name); all the integrity flags of design 4.4 with their audience; privacy between organisations (another organisation's agent is
not named); dedupe of a linked Gantt task and card; the problem rows of a manager's team; an agent's hours never count for its person.

## Choices where the design is silent (builder's calls)

- The cache is two Room tables (settings, one JSON per home snapshot) instead of one table per CalDAV object: simpler, and the
  rows are replaced as a whole only after a source was read completely.
- "Open in NoCalendar" opens the Calendar app on the event's day. The address of one single event is built from the object's own address
  inside the Calendar app, which was not verified against the live app, so it is not used.
- A calendar is read again when its sync token changes (like the desktop client); `sync-collection` / `calendar-multiget` are not used yet.
- Icons in our own chrome are vector drawables; text from the server is shown as it is.
- The colours `#0082c9` and `#00679e` that NoGantt and the calendar give to sources are shown as Nourax cobalt (`#2563EB`).
- A card that a NoGantt task links to is shown once, never twice and never zero times. A card is hidden only when the linked task gives
  a row for the same person in this build (my row; or a team row for that person when I run the project; or the row without a person
  for an unassigned card). A card assigned to me stays when the task is Sara's, nobody's, or done: the open card is still my work.
- A recognised agent by name (rule 4.5 b) is accepted even when its person is not on the task, so it raises "belongs to Sara, not Ali" or
  "agent with no person" instead of "unknown agent"; and a planning person's own `name` counts as well as `uid_display_name`. Both are
  wider than the design text. Both only set a flag and the name match is exact. To be confirmed by the owner.
- A row without a person (a task with nobody, only roles or an orphaned agent; an unassigned card) shows no agent marker: "Self" would
  mean a person does it by hand.
- A row that only reports a problem about my agent ("Writer-Bot is on "X" without you") has no date, so it takes no workload and no
  place in the month grid; it shows under "Problems with your agents" on today.

## Server-side items (not done here; for the Workspace session)

# NoAgenda (Android): editing, the offline queue and edit conflicts (step 2, `feature/noagenda-edit`)

Binding spec: `plans/noagenda-decisions.md` sections 7 and 9. Platform plan: `plans/noagenda-android-plan.md`, section 2 ("agenda-edit").
Everything above describes the read-only core; this part adds what the person can change. Nothing in this step touches a file of the
Drive, and no server is changed.

## What the user gets

- **Edit from the detail sheet.** A row opens its sheet; **Edit** shows the fields of that kind of row:
  an event (title, all day, start and end, description, agent), a to-do (title, start, due, description, agent), a NoGantt task
  (start and end date, percent done, status, agent), a NoBoard card (due date, agent). **Mark done** ticks a to-do, a task or a card.
  **Delete** exists for events and to-dos only, asks first ("Delete this event? It moves to the calendar's trash bin."), and the server keeps
  the object in the calendar's trash bin. A NoGantt task or a card is never deleted here.
- **"+"** (bottom right) makes a **new event** or a **new to-do**: the calendar or list (only ones the person may write to; the server's
  default first), the title, the dates and **who does it: Self (preselected) or one of the person's active agents**.
- **Who does it, person first, then agent.** Choosing the agent of a NoGantt task adds or takes off only the person's own agent
  planning person and never touches anyone else's row. An agent whose planning person is not visible in that project is greyed with
  "Ask your project manager to add Writer-Bot to this project". Paused agents are greyed, retired ones are not listed.
  An invitation is always Self and can't be changed; a repeating event or to-do says "This repeats. Change it in NoCalendar / NoTasks."
  next to **Open in ...**, which opens the signed-in page. A NoGantt viewer sees "You can view this project only. Ask the project manager
  for editor rights."; a task whose progress comes from the board has its percent done read only.
- **Offline queue.** A change is on screen at once, marked **Waiting to send**, the banner counts them ("Waiting to send 3 changes"),
  and they are sent oldest first when the phone is online, also when NoAgenda is closed (WorkManager) and at the start of every refresh.
  The queue lives in its own database and survives a restart.
- **Edit conflicts.** If the item changed somewhere else meanwhile (ETag, `updated_at` or `lastModified` differs, or a 412), the other
  change wins and the list **Not sent** at the top says "This changed somewhere else while you were editing. NoAgenda kept the other
  change." with **Apply my change again** (one fresh read, the same change on top of the new version, one write) and **Keep the other
  change**. A card that a teammate moved to another list is written in the list it is in now, never back where it was. A refusal by the server (not allowed, too many people, a project that allows roles only, the work estimate would change,
  a label that needs board manager rights, a bad date) is said in plain words with **Open in ...** and **Drop my change**. Nothing is
  dropped without a tap. A server in maintenance mode (503, also 502, 504 or `Retry-After`) only makes a change wait, however long it lasts. A
  change that a server error (500 and the like) kept from going out five times shows "The server answered with an error ..." with **Send
  again**, which sends it with the version check it had.
- **After a NoGantt date change** the message says what NoGantt moved ("Also moved: ...") and offers **Undo** for 10 seconds
  (NoGantt's own revert). If a linked card did not follow: "The linked card wasn't moved. Open in NoGantt to confirm."
- **The four conflict kinds and the workload bar** (design 7), computed on the phone: a **Clash** (two timed items of mine overlap;
  a tentative overlap is a **Possible clash**), **Overbooked** (the day's bar says "6 h planned / 4 h free" with a warning when planned
  is more than free; thin bars in the Week view), a **Deadline on a day off** (a due or end date on a holiday, an all-day busy event or a
  day the working pattern does not include) and **Blocked** (as before). The **Conflicts** chip of the Day view keeps only the rows with
  such a badge or that are late. **Agent items never take the person's time**: they never clash with the person's own items, never reduce
  free time, and only the person's own share of work counts for the person. An agent's own overbooking is shown in my day
  ("Writer-Bot is overbooked on Thursday") and, for agents of people I run, in My team.

## Choices where the design is silent (builder's calls)

- **The queue is its own Room database** (the plan said a migration of the cache to version 2): no migration to break, and a problem in
  one file never touches the other.
- A new event or to-do is written with a random UUID as its name and UID; if the answer to the first try is lost, the second try finds the
  same UID on the server and counts as done (no duplicate, no conflict).
- A command that was being sent when the app stopped (it may have reached the server) is sent only against the version the person saw.
  For an event or a to-do, a different version on the server is checked first: when the server's text already has exactly this change
  (only `DTSTAMP`, `LAST-MODIFIED` and `SEQUENCE` differ), the command counts as sent. Otherwise it is a conflict, never an overwrite.
  (A Gantt or Deck change in that state is a conflict when the version moved, even if the move was its own: "Keep the other change" is
  harmless then, and "Apply my change again" is idempotent.)
- A to-do's start and due date are always written in the same value type (sabre/vobject refuses a mixed to-do and the server answers 415).
  The date that is not being changed decides: a due DAY next to a timed start becomes a day and time (the start's time of day); a due TIME
  next to a day start makes the start a day and time (midnight). A start that moves keeps its time of day and its `TZID`. The editors
  refuse a due date before the start.
- A description of 2,000 characters or more may have been cut for the phone, so the editor shows it but does not change it ("This
  description is too long to change here. Change it in the Calendar or Tasks page (Open in NoCalendar)."); the cut text is never written back.
- "+" offers only the person's own calendars and lists that show on the agenda (Personal or Work, not Team, not Hidden). It starts with the
  server's default, then the last one used for events (or to-dos), then the first of the person's own. A team calendar is never preselected.
- The version guard is read again before the first NoGantt or NoBoard change of every run (NoBoard: the capabilities for the Deck version;
  NoGantt: the contract read of NoGantt, as in a refresh). If it can not be read, the change waits; if it is not the tested version the
  change goes to "Not sent" with "version_guard" and nothing is written.
- The three places a change goes to (CalDAV, NoGantt, NoBoard) do not hold each other back: a place that does not answer stops only its own
  changes in that run. A 401 or 403 from NoGantt or NoBoard is a refusal ("does not accept NoDrive's sign-in. Make this change there"), the
  rows of that source are locked, and a 401 from CalDAV still waits (the sign-in is repaired in the app). A server error (5xx) is tried five
  times, then the change moves to "Not sent" ("This change could not be sent.") instead of waiting for ever.
- A NoBoard label switch that loses the network half way puts the labels it took off back (best effort) and remembers the card's new
  version, so the next try is not reported as "changed somewhere else".
- A date change from the sheet sends plain dates (no `adjust_lag`): the person typed the end date, and snapping it to NoGantt's lag rule
  could override it. (Builder's call 20 of the plan said `adjust_lag=true` for the sheet; the Timeline step decides for its own drag.)
- The agent of a Gantt task prefers a planning person that is already on a task of the same project when the agent has more than one.
- An agent of another organisation is never checked for overbooking nor named in My team (design 4.1); a timed card counts in its agent's
  load like a timed event; a Gantt task that starts and ends on one day with real times has clash times.
- A change is stored in the queue first, without waiting for the lock a refresh may hold and in a way a closed screen cannot cancel; the
  send follows. If the screen is closed meanwhile (or the phone is offline), the background send is queued; if the process dies in that
  moment, the 15-minute refresh sends it first.
- A to-do's due date written for a to-do that already has a due time keeps the time of day (there is a time field).
- A Gantt "done" sets `status: done` and, when the progress is manual, `manual_progress: 100`. Percent done of a task whose progress comes
  from the board is read only. NoGantt dates keep the time of day the task had.
- The Deck update is a full replace on the server: the request is always built from the fresh card, always carries `done` (a time, or null),
  never sends the colour. The due date is written in the person's time zone with the time of day the card had.
- A missing label is created with the colour `2563EB` only when the person may manage the board; otherwise "You need to manage this board
  to add the label ...".
- Team rows (other people's work), milestones and rows that only report a problem are not editable here.
- Tentative events count as busy in the free time (the warning errs on the safe side). Holidays are the NoGantt holidays of the person's
  planning person's work calendar, and the ones that have no calendar (for everybody).
- The form says "Percent done" (a bare "%" in a resource string is a format character).
- The Day view's workload bar shows only on days that have planned work; days with nothing planned have no bar.

## Server-side items found here (for the Workspace session; this step changes no server)

See also section 5 of `docs/testing.md` (S18 to S22) and section 6 of `plans/noagenda-android-plan.md`.

- NoGantt's task update has no version precondition (no ETag, no `If-Match`), and Deck's card update is a full replace without one either. The app reads the item right
  before the write and compares `updated_at` / `lastModified`; a short race remains. A precondition (or a 409) on both would close it.
- Calendar and Tasks keep both agent marks when a person edits an event or a to-do in their pages. Re-run `agenda-server` (it includes this check) before updating Calendar or Tasks.
- The Workspace AI tools must write the agent of an event or a to-do exactly as NoAgenda does: `X-NOURAX-AGENT-ID` plus the registry's `calendar_tag` in `CATEGORIES`.

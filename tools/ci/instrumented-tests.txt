# Instrumented test classes that CI runs on the emulator for the nodrive flavour
# (tools/ci/device.sh). All of them work without a Nextcloud server. Methods marked
# @com.nextcloud.test.Flaky (upstream) or @ScreenshotTest are filtered out with notAnnotation.
# When at most 5 methods fail, device.sh runs just those once more; the job passes only if they
# pass then. The retry and the first run's results are in the step summary and the test report.
#
# Not run, with the reason (nothing is skipped silently):
# - every subclass of AbstractOnServerIT (FileIT, UploadIT, DownloadIT, FileDisplayActivityIT,
#   OwnCloudClientManagerTest, UserAccountManagerImplTest, AssistantRepositoryTests, ContactsBackupIT,
#   ConnectivityServiceImplIT, AutoRenameTests, FileNameValidatorTests, GrantFolderExistenceTests,
#   FileDataStorageManagerIT, FileUploaderIT, DeleteE2ERemoteOperationIT,
#   GetSharesForFileOperationIT, RemoveFileOperationIT, DocumentsStorageProviderIT,
#   PreviewImageActivityIT): they need a Nextcloud test server; CI cannot sign in (spec section 7).
# - FileDataStorageManagerContentProviderClientIT, FileDataStorageManagerContentResolverIT: they
#   extend FileDataStorageManagerIT, an AbstractOnServerIT.
# - com.owncloud.android.ui.LoginIT: types a server address into the server field, which NoDrive
#   does not have (fixed server), and then signs in to a test server.
# - the @ScreenshotTest classes: they record images for upstream's Shot comparison (API 28 only);
#   tools/ci/sweep.py takes real screenshots of the installed app instead.
# - androidTest/disabledTests: switched off upstream.
# - org.nourax.nodrive.NoDriveSweepAccount: not a test; sweep.py uses it to add a local account.
#
# Single methods left out (lines starting with "-", passed as notClass), with the reason:
# - On Android 13+ (CI emulator: API 35) the app asks for the notification permission, and the
#   system dialog (permissioncontroller GrantPermissionsActivity, seen in each test's logcat) covers
#   the activity under test, so it never reaches RESUMED. Upstream's CI runs these on API 28.
-com.owncloud.android.ui.activity.FileDisplayActivityTest#testSetupToolbar
-com.nextcloud.ui.SetOnlineStatusBottomSheetIT#open
-com.nmc.android.ui.LauncherActivityIT#testSplashScreenWithEmptyTitlesShouldHideTitles
# - The result depends on the emulator's storage environment variables (EXTERNAL_STORAGE,
#   SECONDARY_STORAGE); on the API 35 image "/sdcard/" comes back as "sdcard/". No branding involved.
-com.owncloud.android.utils.FileStorageUtilsIT#testPathToUserFriendlyDisplay
# - Starting account creation in NoDrive is the fixed-server sign-in: AuthenticatorActivity posts to
#   drive.nourax.org and opens the browser, which stays in front and takes window focus from the
#   tests after it (run 40163420586: InjectionTestActivityTest, UsersAndGroupsSearchProviderIT).
#   tools/ci/sweep.py tests this sign-in flow on purpose.
-com.owncloud.android.utils.SessionMixinTest#startAccountCreation
# - Upstream test that depends on the clock: it expects "2 hours ago" and gets "Yesterday, 23:xx" whenever
#   the run starts within two hours after midnight UTC (run 40430238655, 01:10 UTC). No branding involved.
-com.nextcloud.utils.UploadDateTests#getRelativeDateTimeStringReturnsRelativeStringForHoursAgo
